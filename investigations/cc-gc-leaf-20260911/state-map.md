## What already exists

- `crates/perry-codegen/src/gc_call_effects.rs:18–35,301–315` defines `CannotCollect`, `AllocNoReentry`, and conservative `Unknown`. The first means no route into Perry collection, not allocation-free: raw Rust/system allocation, registry updates and some marking-barrier work qualify. The exact-name table already includes many NaN-box/typed guards, temp/shadow roots, layout notes, write barriers, box/closure accessors and pure dispatch probes. Throw helpers, coercing helpers and generic property operations cannot be classified merely from a cheap common arm.
- `AllocNoReentry` is conditional. Codegen's `helpers.rs:259` enables it only with `PERRY_GC_SAFEPOINT_ONLY` equal to `1/on/true/strict`. Runtime `gc/policy.rs:1139–1216` gives `1/on/true` the **Heal** contract (an undeclared precise-root collection forces a conservative scan for that whole nonmoving cycle), while `strict` rejects that collection. Unset is Off. It is therefore wrong to call these unconditionally collection-free or to enable this mode as a mere compiler optimization. Both compile-time and runtime contract settings matter.
- `gc_call_effects.rs:452–543` computes the module-wide greatest fixed point: reject functions with unaudited external/indirect/collecting edges, propagate rejection through direct calls, retain closed recursive components. `module.rs:582,717` computes it before codegen-unit partitioning. Direct generated leaf calls are already marked `gc-leaf-function`; this is not an unimplemented opportunity. Definitions in another source module are conservatively external unless separately certified.
- `function/precise_roots.rs:145–223,251–307` turns existing bound root allocas into `ptr addrspace(1)` allocas, initializes them, rewrites accesses, removes shadow bind/set calls, and marks audited direct runtime **call** sites leaf. It retains the root reload's tied-register identity asm (`:35–83`); that is zero-instruction compiler bookkeeping, not a runtime helper call. Unrecognized root accesses stop compilation rather than silently choosing a different representation. `function.rs:969–1008` applies module leaf annotations and retypes exceptional pads. Explicit proven callsite leaves can also occur on indirect calls (`block.rs`); their guarded provenance must not become a general indirect-call claim.
- The native roots default is target-aware (`codegen/helpers.rs:215–250`): x86-64/AArch64, excluding arm64_32 and non-x86-64 Windows. Unsupported targets use the precise shadow frame. `PERRY_RS4GC` can explicitly override selection. Within a supported module, very large functions can separately retain shadow frames: source estimate, actual preflight root/call estimate, and post-rewrite instruction budget all exist. `native_emit.rs` retries only the affected unit/function with its shadow representation, preserving the optimization level. A module-wide native flag therefore cannot classify each function's root representation.
- `linker.rs:37` supplies the actual shared pre-rewrite pipeline: `always-inline,function(mem2reg,sccp),rewrite-statepoints-for-gc`. `inprocess/optimize_emit.rs` runs it before ordinary `default<O*>`, verifies rewritten IR, applies existing retry/backstops, then optimizes and emits. Captures before/after this pipeline include the effects of always-inline, mem2reg and SCCP as well as RS4GC; their delta is not solely the rewrite pass.
- Emitted statepoints describe suspended caller frames; a caller can require one even if the caller itself neither allocates nor polls. Removing all call edges except explicit polling calls would discard caller-frame descriptions beneath collecting callees. Conversely static statepoint counts are not executed helper-call counts or GC collection counts.

## Existing barriers and prospective questions

`expr/write_barrier.rs:27–107` already omits whole barriers when codegen barriers are disabled and uses a pointer-bearing value admission. The generation-tested path (`:170–235,286–318`) skips the helper only when the parent is not tenured **and** no incremental mark barrier is active; the validated-parent variant avoids another header classification after that proof. Numeric/pointer-free construction and typed-layout work have their own existing specializations. `lower_call/ctor_prologue_stores.rs:83–90` explicitly retains pointer/boxed-field barriers even for a fresh unpublished instance, for old-generation/incremental correctness.

A fresh-allocation census is useful; “fresh” alone does not imply nursery/non-tenured, pointer-free, or no incremental marking. It must use audited allocation-return summaries, preserve layout notes, intersect facts at CFG joins, and end facts at any possibly collecting/re-entering edge. It counts emitted candidate barrier sites, not calls that execute or a justified removal.

Possible follow-ups, only if the actual census warrants them:

1. Rank residual runtime call/statepoint pairs whose complete implementations could be certified CannotCollect. The existing table makes a broad leaf rewrite redundant. A helper may allocate outside Perry yet qualify; a nominally nonallocating helper may invoke user code and fail.
2. Check representation coverage before adding a new classification: the runtime helper annotation in `precise_roots` recognizes direct `call` text, whereas module-leaf annotation handles `call` and `invoke`. Some audited helpers are already emitted nothrow and will never become invokes (`block.rs:1326`, `eh_mode.rs:78`). Count the actual remaining audited-helper invokes before proposing any extension.
3. Count fresh-parent barriers surviving existing value/generation guards, distinguishing a helper call from the preceding inline checks. Do not drop incremental shading or layout metadata based on age alone.

Recommendation: keep this round observational. There is no source-grounded estimate yet showing a worthwhile missing optimization; skip implementation if residual sites have low dynamic relevance or require stronger lifecycle facts than the runtime provides.

## New diagnostic transport

`PERRY_GC_LEAF_CENSUS_DIR=<fresh-directory>` enables a lossless bitcode capture only in the in-process LLVM backend. The output-directory lookup is cached; when absent, no LLVM serialization, diagnostic allocation/file work, or runtime code is added. When enabled it adds compiler-side serialization and file I/O, so compile timing is diagnostic. Failed output is reported, never substituted into codegen and never used to choose a pass or root representation.

Each invocation creates an exclusive `pid-<PID>-attempt-<ordinal>/` directory containing:

- `attempt.json`: schema 1, PID, ordinal, module identifier, effective target, requested native-root flag, IR optimization level, assembly/object mode and `snapshot_format=llvm-bitcode`.
- `pre-rs4gc.bc`: after target/data-layout setup, before preflight and the shared rewrite pipeline.
- `post-rs4gc.bc`: after the verified rewrite but before the post-rewrite retry budget. For native_roots=false the unchanged-stage snapshot exists and the metadata explicitly identifies the skipped rewrite.
- `post-opt.bc`: after the actual default optimization pipeline, before machine emission.
- `complete.json`: schema 1, `status=llvm-emission-succeeded`, ordered three filenames/byte lengths, emitted-buffer length and whether the existing bounded O0 machine-emission fallback was selected. Written only after emission returns successfully.

No `complete.json` means **unavailable/abandoned**, never zero. Repeated/out-of-order stages or any snapshot I/O failure prevent completion. JSON must parse completely and all lengths must agree. The complete marker means LLVM memory-buffer emission, not later assembly, codegen-unit combination or final linking. Bind analysis to the successful outer compiler job and accepted unit/object receipts as well. Native construction currently repeats `perry_native_module` as its module identifier; derive retry/unit matching from the sorted defined-function set in the pre snapshot, not the module string or worker order. Keep every attempt in the record but total only accepted successful emissions once. If two successes for the same unit cannot be distinguished, do not silently sum them.

Use matching LLVM 22 `llvm-dis <snapshot.bc> -o -` to stream full IR into the analyzer. Attribute groups preserve `gc-leaf-function`; classify callsites using inline and grouped attributes. Native-vs-shadow is a per-function fact: GC strategy `statepoint-example`, retained shadow-frame helpers, or neither; do not call every function lacking a GC strategy shadow-rooted. Statepoints preserve actual callee operands, block names, gc-live bundles and exceptional continuations; count instructions, not declarations. Relocates can outnumber distinct roots because of exceptional paths/base-derived handling. Inline asm and LLVM intrinsics are separate categories, not runtime helpers. Static-user versus external-runtime classification needs the complete definition/callee inventory; symbol prefixes alone are a weaker label.

The variable is a build-cache exclusion because it cannot change emitted code. It does **not** bypass either cache itself. `--trace llvm` sets `PERRY_NO_CACHE=1` (`run_pipeline.rs:658–677`); explicit `--no-cache`/`PERRY_NO_CACHE=1` also disables object-cache lookup (`:2574–2583`) and the whole-build cache (`build_cache.rs:892`). Use the coordinator's exact no-cache recipe; a cache hit has no diagnostic row. The external clang/opt path is not instrumented and must not be mistaken for empty output.

## Actual compact-map cross-check

The retained binary's `.perry_gcmap` is the appropriate final-artifact comparison; `.llvm_stackmaps` is intentionally consumed and replaced. The coordinator reports section size `0x16e5b90` and offset `0x15359760`; this lane did not reread/hash the binary. `.eh_frame` and its header are separate unwind metadata.

The exact compact format is **PGCM version 5**, not raw LLVM stackmap format. `perry-codegen/src/gc_map.rs:59–74,1007–1117` is the emitter/layout authority. `perry-runtime/src/gc/roots/stack_maps_lazy.rs:349` is the production lazy function-table parser; `stack_maps_decode.rs:29` is the full decoder. At each little-endian blob: magic[4], version u8, reserved u8, flags u16, function_count u32, total_len u32; 64-bit function entries are address u64 + stack_size u32 + record_count u32. These are followed by one u32 stream offset per function, all u32 instruction offsets, then the compressed root stream. Walk concatenated blobs using total_len, respecting padding and bounds. Sum record_count for an actual map-record count; decode the root stream to count root/derived descriptions. Repeated-live-set encoding means byte size is not root count. Map records and post-opt statepoints may differ through final emission/linking; report differences, do not force equality.
