# Fresh-allocation barrier census — conservative coverage only

A same-function allocation origin is useful evidence, but **does not prove the owner is young, unexposed or exempt from a write barrier**. The initial analyzer counts explicit emitted generational-barrier entry sites reachable from a known allocation return with no intervening possibly-collecting call. It makes no elision or CPU claim.

## Existing mechanics that must stay separate

`expr/write_barrier.rs:27` emits the compatibility barrier behind a pointer-bearing child check. `:104–188` derives the live parent predicate from TENURED plus `PERRY_INCREMENTAL_MARK_BARRIER_ACTIVE_COUNT`;`:209` and`:285` emit exact-slot variants, including a value-first gate. The runtime's remembering work follows the incremental child prologue (`gc/barrier/mod.rs:1241`,`:1327`), and`:1591` treats old arena/external malloc parents appropriately. A generational proof cannot erase the incremental shading obligation. The runtime trace counters at`:1183` count entry/skip/remembering outcomes; they do not include codegen gates that avoided entry, so those counters alone cannot estimate all inline-gate cost.

Root stores (`write_barrier.rs:336,343`) shade registered roots and are not heap-parent generation questions. Layout notes (`:359,375`) describe which slots the collector must visit; freshness does not make them optional. Old-to-new pointer transitions also differ from pointer-to-scalar layout transitions. String sharing is a separate semantic effect: `gc/barrier_store.rs:103` canonicalizes, writes, marks a heap string shared, notes layout, and executes the barrier. The retained `object/live_slots.rs:104` already removes generic slot validation for known-live stores while retaining that common body. Do not price all of those effects as a generational barrier.

Already-elided population: small inline array literals (up to16, `expr/array_literal.rs:127–242`) evaluate values first, initialize a nursery-format header, preserve necessary layout/string notes and pass `write_barrier_needed=false` for their initialization stores. They are not a new optimization opportunity. The larger literal fallback (`:254–278`) calls `js_array_alloc_literal` and still emits relevant pointer-bearing slot barriers; these are reasonable census candidates, with generation still unproved. Outlined literal construction (`:108`) hides the stores in `js_array_from_values` and is excluded from an explicit compiler-barrier count.

Object literal construction (`expr/object_literal.rs:370–550`) allocates its owner before evaluating initializers, roots it when an initializer may collect, then writes indexed fields through runtime setters. `{a: x, b: call()}` must lose the earlier owner's freshness at that call. The source comment saying an allocator returns a fresh pointer means a new logical object, not a nursery guarantee. `arena/allocators.rs:414–443` explicitly births large objects in old generation with TENURED. `object/alloc.rs:741` constructs the object before finishing shape/key publication. Even a small owner may encounter other work inside a constructor before return. Inline constructor methods can publish `this`; analysis must not infer nonescape from `new` syntax.

## Analyzer contract and use

`fresh_barrier_census.py` is a standalone Python observer, without compiler/runtime edits. It parses LLVM printer text by function/basic block, constructs successors/predecessors, ignores unreachable blocks, and computes conservative forward facts. An exact return from the listed fresh object/array/closure allocators creates an allocation-origin identity **after** killing earlier facts. Cached closure singletons, input-returning constructors and raw allocator-header pointers do not qualify. Facts propagate through SSA `bitcast`, `ptrtoint` and `inttoptr`; memory loads, `getelementptr`, NaN-box arithmetic, `phi`, `select` and other operations do not recover an alias. Every CFG join kills facts; single-predecessor chains preserve them. This intentionally misses valid merge proofs rather than manufacturing them. Allocating invoke results are not admitted on either successor; unknown/indirect calls kill the set.

The three counted ABIs are `js_write_barrier`, `js_write_barrier_slot`, `js_write_barrier_slot_validated_parent`; argument0 is the owner. Root barriers and layout notes are never counted as removable work. Hidden barriers inside runtime property/array setters are not visible and not counted. Post-RS4GC `gc.result`/`gc.relocate` and inlined allocator arithmetic are currently unsupported as allocation aliases, so pre-RS4GC is the primary census. Post-opt counts are only residual directly recognized sites, not a matched before/after subtraction.

Strict propagation accepts a small exact already-audited bookkeeping set plus optional `--noncollecting-callees audited-cannot-collect.json`. That input must contain **CannotCollect** summaries only. `gc-leaf-function` by itself is deliberately insufficient: `gc_call_effects.rs:20–29` and`:307` permit `AllocNoReentry` statepoint exemptions under SAFEPOINT_ONLY while describing an allocation-point conservative-collection valve. A root-map exemption is not always a no-collection proof. `--extra-leaves candidate-leaves.json` separately counts additional sites obtained only if proposed runtime helpers become truly noncollecting; strict counts are unchanged. Allocation helpers always kill older facts even if named in either list.

Example after root converts a completed bitcode snapshot using the same LLVM22:

```sh
python3 -B fresh_barrier_census.py --ir /owned/dump/pid-P-attempt-N/pre-rs4gc.ll --attempt-dir /owned/dump/pid-P-attempt-N --noncollecting-callees /owned/audited-cannot-collect.json --extra-leaves /owned/candidate-leaves.json --output /owned/barrier-counts.json
```

`--attempt-dir` requires parseable attempt/complete JSON and text in that directory; the converter and root must separately bind `.ll` to the original `.bc` hash, selected stage, accepted object and executable. The analyzer does not claim that existence of `complete.json` proves linking. Inputs and summary lists are hashed. Unsupported CFG terminators yield explicit excluded-function records and exit2: retain partial results as partial, never interpret excluded functions as zero. No attempt filtering is inferred from filesystem time or similarly named files.

Each reported hit means only **known allocation identity since the last potentially collecting edge**. Generation is explicitly `unknown: fresh return may be old or published`; publication is not analyzed. A future valid elision still needs a size/type/birth-path proof for a non-tenured parent, no intervening promotion, correct physical slot owner (spill backing may differ from object receiver), current reference-layout notes and independent incremental-cycle handling. Heap publication and aliasing require separate lifetime reasoning. Do not add the counts to broad GC or callee self percentages.

## Focused validation performed

`python3 -B -m unittest test_fresh_barrier_census -v` passes11 parser/dataflow tests. They cover real alias propagation/single predecessors, collection kills, separate hypothetical leaf arm, second allocations, joins/backedges, loads/arithmetic decline, indirect-callee identity, statepoint-leaf-vs-CannotCollect distinction, unreachable code, allocating invoke exclusion, cached singleton exclusion and unsupported CFG refusal. These are textual analyzer witnesses, not LLVM verifier or runtime GC tests.

Two sabotage controls actually change the analysis policy: removing the allocator summary breaks the positive expectation; falsely declaring a collecting helper noncollecting breaks the negative expectation. Both expected assertion failures are observed. No Cargo, native build, runtime probe, box job, profile or timing was run. The forthcoming real LLVM inputs remain unmeasured; their unsupported patterns will be reported rather than silently generalized.
